The run you are reading about

Imagine you have two toy cars that are connected in a special way, so that if you make one car spin around, the other car will start spinning around too, even if it's on the other side of the room. This is kind of like what happens with quantum entanglement, where two tiny particles can be connected in a way that lets them talk to each other and do the same things, even if they're really, really far apart.

What changed in the code

  1. The crash

    SambaNova closes a stream with a usage frame that carries an empty choices list. chunk.choices[0] raised IndexError on the final chunk, every time, after the answer had already been generated — so the run always died just before writing audio. Skipping choice-less chunks fixes it.

  2. The clock started too early

    The stopwatch began before websocket_connect(), so 2.2 s of handshake was billed to the language model. "First token" read 3.9 s when the model was really answering in 1.67 s. In production that socket is already open when the user speaks, so it does not belong on the clock at all.

  3. Timings survive the run

    Each run now writes output/timings.json alongside the WAV, and reports synthesis rate against realtime — the number that decides whether audio can stream straight to a speaker or has to buffer first.

Measured over residential wi-fi from a single warm run. Network conditions move these numbers more than anything in the code — treat them as a shape, not a benchmark.
